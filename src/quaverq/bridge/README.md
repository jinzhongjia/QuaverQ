# src/quaverq/bridge

**Python ↔ QML 桥接层**。每个文件导出一个 `QObject` 子类（或 `QAbstractListModel` / `QQuickImageProvider`），通过 `engine.rootContext().setContextProperty(...)` 注入 QML 上下文，把 [`core/`](../core/README.md) 的能力以 `Property` / `Signal` / `Slot` 暴露给 QML 直接绑定。

控制器持有 `core` 的对象、订阅其回调，再把变化以 Qt 信号广播给 QML；反过来，QML 调用 `Slot` / `asyncSlot` 触发业务动作。任何会阻塞或走网络的逻辑都用 `qasync.asyncSlot` 在事件循环里跑，绝不阻塞 UI 线程。

| `app_controller.py` | `AppController` | 应用级状态：登录态、二维码扫码登录流、凭据过期通知、深色模式切换、`appVersion` 常量属性（`application_version()` 读包元数据，读不到回退 "dev"）。扫码登录流的 QQ/微信 快速切换由 `_login_lock` 串行化（“取消上一个 + 登记本次”原子化、长轮询在锁外 await），任意时刻仅一个轮询循环存活、切走的旧轮询全部取消，防止孤儿循环在登录成功后仍后台刷“等待扫码”。账号画像（C4 侧栏身份区）：`nickname` / `avatarUrl` / `vipKind`（""/vip/hugevip/svip）/ `vipIconUrl` 四属性 + `profileChanged` 信号；`_set_authed` 变 true（login / cached prime）时 fire-and-forget 拉 `ServiceController.get_user_profile()`，变 false（登出/过期）同步清空并取消在途任务，迟到结果按当前 authed 丢弃（竞态保护）；拉取失败仅 log warning，身份区静默缺席不挡登录主流程。画像走 `HomeCache` SWR：启动期 `prime_profile_from_cache(account_key)` 同步喂缓存首帧（engine.load 前，不联网），网络刷新成功后回写缓存（`_persist_profile`，带 account_key 归属），同值刷新经 dataclass 相等去重零跳变；登出缓存清理由既有 `clear_private()` 链路覆盖。 |
| `service_controller.py` | `ServiceController` | QQ 音乐服务层（`core.service.QuaverService`）的 QML 包装：搜索、详情、首页 API。账号 key、凭据预热、网络有效性校验都在这里。`start()` 记录 `perf service.start` 耗时日志。搜索请求走 generation + active task 管理：新关键词 / 切分页会取消旧请求，迟到结果与错误按 generation 丢弃，避免快速输入时旧结果回填。搜索类型 `searchType` ∈ `general`(综合, 默认+首个 tab) / `songs` / `singers` / `albums` / `playlists`：`general` 走 `service.general_search`，单曲灌进 `songResults`、相关搜索词进 `relatedWords`（`[{display, keyword}]`, 可点 chip 再搜）、首个可导航直达进 `directHit`（card 形态, kind 已映射成 `detailRequested` 用的 `artist`/`album`, 无则 None）, 综合不翻页（`hasNextPage` 恒 False）；切到其他 tab / 空关键词 / `clear()` 都会清空 `relatedWords` + `directHit`。`songs` 走分页 `search_songs`，其余走 `cardResults`。`loadHotSearches()` slot 懒加载热搜词到 `hotSearches`（`get_hot_search`，已加载则跳过、失败静默允许重试），供空搜索页展示。`requestSuggest(keyword)` slot 拉输入联想到 `searchSuggestions`（`get_search_suggest`，debounce 在 QML 端做；用 generation 保证只有最新一次输入的结果生效，迟到结果丢弃；空词不打网络直接清空），`clearSuggestions()` 作废在途请求并清空。`get_lyric(mid)` 带运行期内存缓存与 in-flight 去重：同一首歌多入口并发拉取只打一条网络，成功后本次运行内切回直接复用；失败不缓存。`get_user_profile()` 走 `call_service` 统一凭据过期处理。`resetRiskFingerprint()` slot 重抽并落盘 vkey 用的 ct 值（`service.reset_risk_fingerprint`，本地写 + 立即生效、不联网），成功发 `noticeRaised` 提示（设置页"重置风控指纹"按钮）。 |
| `home_controller.py` | `HomeController` | 首页发现：每日推荐 / 今日歌单 / 新歌速递 / 排行榜。SWR：先用 `home_cache` 同步喂首帧，再后台 `refresh_*_async`；`refresh_home_async` 与各 section 记录 `perf home.refresh_*` 耗时日志。猜你喜欢 (`daily`) 走 `DAILY_TTL_SECONDS = 6h` 门：启动 / 登录态变化触发的自动刷新若缓存还新鲜则跳过网络；只有用户主动从 QML 调 `refreshHome()` / `refreshDailyThirty()` 才 `force=True` 穿透 TTL。注入 `PlayerController` 后联动：`dailyPreviewSong` 跟随播放中曲目；监听 `queueExhausted("daily")` 自动 `extend_daily_async()` 续取下一批并 `append_to_queue` 续播。 |
| `library_controller.py` | `LibraryController` | 资料库：我喜欢、我的歌单、收藏歌单、收藏专辑、关注艺人，登录后从 `home_cache` 私有区块同步首帧再刷新。每个 section 的刷新走 in-flight 复用：QML 切 tab / 登录态变化重复触发同一 section 时只打一次接口，后到调用 await 现有任务；真实执行刷新的任务记录 `perf library.refresh_section` 耗时日志；`loading` 由 `_loading_sections` 汇总，多个 section 并发时不会提前熄灭。 |
| `detail_controller.py` | `DetailController` + `DetailControllerFactory` | 歌单 / 专辑 / 艺人 / 排行榜详情页状态：标题、封面、曲目列表、loading / error。歌手详情页扩展：`similarSingersModel` / `singerSongsModel` / `singerAlbumsModel` 三个懒加载 model（`loadSimilarSingers` / `loadSingerSongs` / `loadSingerAlbums` slots），切歌手时自动 reset；用 `*Loaded` 标志保证幂等。**Controller 走 factory 模式**：每个 `DetailView` push 入栈时 `factory.create(view)` 拿到独立实例（Qt parent=view, GC 自动），避免栈式 view 共享 singleton 导致 pop 后 state 错乱（见 [AGENTS.md](../../../AGENTS.md) 契约 1）。 |
| `song_detail_controller.py` | `SongDetailController` | 歌曲详情 popup 状态：currentSong + similarSongsModel + relatedPlaylistsModel + **songInfo (dict, 2.4 加入)** + visible，由 SongRow 右键 / 菜单键触发 `open(song)` 异步并发拉相似/相关/歌曲附加信息。`load_generation` 防 race，关闭时保留旧 model 内容不闪空。 |
| `player_controller.py` | `PlayerController` | 播放器：包装 `QMediaPlayer` + `core.queue.PlayQueue`。控制四种播放模式、音质偏好、进度/音量/静音（`muted` 独立标志不动音量值，`toggleMute()` 切换；`setVolume`/`nudgeVolume(delta)` 任何主动调音量自动解除静音；静音不入会话快照）、退出快照保存（`session_state`）。服务端明确拒发的曲目（vkey `result=104003` 无版权等灰色歌曲）**自动跳下一首** + `noticeRaised` 轻提示（连跳上限 5 防全队列不可播时绕圈空转；传输层异常仍停住报错，断网不会把队列"跳"光）。待播队列的单点变动（追加/插队挪位/单行移除）走 `SongListModel` 的**粒度信号**（insert/move/remove rows），整表 reset 仅用于整队列替换——reset 会让待播面板的 ListView 重建并滚回顶部（真机验收反馈）。`play_songs_async(songs, idx, source=...)` 可给队列打来源标签 (e.g. `"daily"`)；队列自然耗尽时发 `queueExhausted(source)`，外部 `append_to_queue(songs)` 追加后自动续播。**预取下一首**（issue #11）：起播稳定后（`playing` 信号 + 5s 延迟）后台取 `queue.peek_next()` 的播放链接缓存单条；`_load_current` 消费时 mid + 音质偏好双匹配才命中、消费即清（媒体错误重试必现签新链）、失配即弃；预取失败/拒发静默，自动跳过通知等用户可见逻辑留给正常链路；队列结构/模式变化（`setMode` / 插队 / 移除非当前曲）走 `_refresh_prefetch` 让旧预取失效并按新下一首重取。**REPEAT_ONE EOS 短路**：链接未变时回卷重播（`seek(0)+play`），不重取链。**切歌淡出协调**（`fadeOutRequested(durMs)` 信号）：正在出声时切歌先发淡出并保留旧 source（清了立即哑），取链与淡出并行（fade 时长掩盖网络延迟），淡出播完才换源；窗口内 `updatePosition` 冻结（UI 已显示新歌，不让旧歌进度拽回进度条），错误路径卸源解冻；淡出 `asyncio.sleep` 期间用户暂停的意图（`_pause_pending`）会被保留，不被淡出结束后的起播覆盖；fade 关闭 / 非出声态走旧行为。**流末尾解码豁免**：CDN FLAC 尾部坏帧让 QMediaPlayer 在末尾 emit `FormatError`，当 position 落在末尾窗口 `max(duration-5s, duration//2)`（短歌也用 `duration//2` 兜底，开头/中段真损坏仍报错）时静默忽略，由 EndOfMedia 接管切歌，不误报「播放失败」。**本地优先播放**：注入 `local_resolver`（`DownloadController.local_path_for`）后，`_load_current` 对已下载且文件仍在的歌直接 `QUrl.fromLocalFile` 播放、跳过预取消费 / vkey 取链 / stream_proxy（离线/未登录也能听），淡出等待与挂源走公共尾部（淡出/暂停意图行为与在线一致），文件失效或解析异常自动回退在线。**StreamProxy 懒启动**：只有在线播放需要代理 URL 时才 `start()`，启动失败保留 `local_url()` 的直连降级语义；本地优先命中不会启动代理。 |
| `lyric_controller.py` | `LyricController` | 同步歌词：跟随 `player_controller` 的进度更新 `activeIndex`，逐字 karaoke 高亮的进度也在这里算。构造期会主动读取一次 `PlayerController.currentSong`，补上 `PlayerController` 已从 `state.json` 恢复队列/进度但 `LyricController` 尚未连接信号的启动窗口；若注入 `LyricCache`，当前 mid 命中时先同步填模型，主窗口 / 悬浮歌词首帧可直接显示上次歌词，再由 `_load_initial_state()` / 切歌信号后台刷新并回写缓存；刷新失败保留已 prime 的歌词并只更新错误状态。 |
| `download_controller.py` | `DownloadController` + `DownloadListModel` | **音乐下载编排**：`asyncio.Queue` + 单 worker 串行（并发 1，避免 vkey/CDN 风控、不与播放抢带宽）。每首流程：`get_song_url(下载音质 profile)` → `core.Downloader` 流式落盘（`to_thread`，进度经 `call_soon_threadsafe` 节流回灌 model）→ `.lrc`（`get_lyric` + `to_lrc`，UTF-8）→ `.jpg` 封面（`cover_url_for(mid, 500)`）；歌词/封面失败不致命；下载完成后按 `downloadEmbedTags` 用 `embed_tags` 内嵌标签（标题/歌手/专辑 + 旁置封面图，失败同样非致命）。文件名 `歌手、歌手 - 歌名 [音质].<ext>`（`sanitize_filename` + 音质短标识，区分换音质重下/同名翻唱避免误判跳过），同名已存在跳过 + `noticeRaised`；入队即发 `noticeRaised("已加入下载")` 即时反馈。注入 `DownloadStore`（`core/download_store.py`）做**持久化**：任务 `done` 时 `store.add(record)`（song + 本地路径 + 音质 + 大小 + 时间戳）；构造时 `_load_history()` 从 `downloads.json` 把历史填进 model（文件仍在标 `done`、已被外部删除标 `missing`），**重启后下载页保留记录并反映失效**；`_cancel_events` 按 mid（非 row）存，移除历史行致行号偏移后仍能正确取消。QML API：`downloadSong(song)` / `downloadSongWithQuality(song, q)` / `downloadFromModel(songListModel)`（批量，跳过缺 mid 与已在队列中的曲目）/ `cancelTask(row)` / `retryTask(row)`（failed/canceled/missing 重新入队，文件失效的用当前设置音质重下）/ `openDownloadDirectory()` / `local_path_for(mid)`（返回已下载且文件仍在的本地路径，供 PlayerController 本地优先播放）/ `removeTask(row)`（从列表 + `downloads.json` 移除一条记录，清理失效/历史死记录，**不删**音频文件本体）/ `deleteTask(row)`（**删除已下载音乐**：删本地音频 + 旁置 .lrc/.jpg + 记录 + 列表行，进行中需先取消、文件已不在也容忍；UI 侧带二次确认）；`downloadModel`（title/singers/status/statusText/progress/qualityText/errorText/destPath/**coverUrl/song** roles，progress=-1 表示长度未知）+ `activeCount`；信号 `downloadFinished(message)`（**完成提示聚合**：worker 队列清空时一次性发，单首「已下载：X」/ 批量「已下载 N 首」，避免逐首刷屏）/ `errorRaised` / `noticeRaised` 由 Main.qml 接 Snackbar。退出时 `shutdown()` 置位取消事件清 `.part`。 |

| `audio_device_controller.py` | `AudioDeviceController` | **音频输出设备选择（issue #7）**：用 `QMediaDevices` 枚举输出设备，暴露 `deviceLabels` / `deviceValues`（首项「跟随系统默认」/空串，值为 base64 编码的 `QAudioDevice.id()`）给设置页 `ChoiceRow`；QML 侧 `audioOutput` 在 `Component.onCompleted` 经 `attachAudioOutput()` 交给 Python 托管 `setDevice`。选择经 `selectDevice(value)` 写入 `SettingsController`，实际应用由 `settingsChanged` 信号驱动（幂等 apply）。**软回退**：所选设备拔出 → set null `QAudioDevice` 回退系统默认但**不清**偏好，模型末尾附「xxx（已断开）」占位项，插回经 `audioOutputsChanged` 自动恢复；「跟随系统默认」= 不显式 `setDevice`，保持 Qt 后端对系统默认切换的自动跟随。纯事件驱动（`audioOutputsChanged` + `settingsChanged`），不轮询。 |
| `desktop_lyrics.py` | `DesktopLyricsWindow` + `DesktopLyricsController` | **桌面悬浮歌词（仅 Windows）**：frameless + 透明 + WindowStaysOnTop + Tool + WindowTransparentForInput 的 QQ 音乐风格桌面 OSD。逐字高亮：`set_line(text, words)` + `set_progress_ms(ms)`，用 `ms >= startMs` 算 sung_count（与 `LyricPanel.qml` 一致）；无 `words` 数据时整句视为已唱用 highlight 色，但会用当前行 / 下一行 timestamp 计算行级滚动进度。`QPainterPath.addText` 描边 + 分段填色；竖排走**统一块模型**：CJK（含全角 / CJK 标点）正立逐字堆叠，其余一切（拉丁 / 数字 / ASCII 标点）按连续段整段旋转 90°（无脑化，借此消除缩写直立、制作行整行旋转、按词拆分等边界 case）。旋转 Latin 块用真实路径 bbox + 描边余量计入高度，避免末尾字符被窗口裁掉。横排 / 竖排超长歌词保持用户字号不缩放，按当前逐字进度或行级进度滚动到可视范围；竖排双列（歌词右列 + 翻译左列）按两列内容盒中心线对齐，长翻译不再从主歌词顶端开始排。**记住拖动后的位置**：解锁拖动结束发 `geometryEdited` 信号，Controller 回写 `SettingsController`（横 / 竖各存一份，因两方向默认几何差异大）；恢复时按当前方向取记忆位置并 clamp 到屏幕可用区，离屏 / 拔副屏自动回默认；锁/解锁切 `setWindowFlags` 前后保留几何防复位。Controller 接 `LyricController.currentLineChanged` / `positionMsChanged` + `SettingsController.settingsChanged`，每次全量 pull 状态（geometry 在 apply 前先推给窗口，故方向切换能定位到记忆位置）。Linux / macOS 不接（PAL 返 None；见 [platform/README.md](../platform/README.md)）。 |
| `mpris_controller.py` | `MprisController` | 把 `PlayerController` 的状态/元数据推到 `core.mpris.MprisService`，从 D-Bus 收到的方法调用回灌到播放器。 |
| `lyric_dbus_controller.py` | `LyricsDBusController` | 把 `LyricController` 当前歌词 + `PlayerController.positionMs` 推到 `core.lyric_dbus.LyricsService`（`org.quaverq.Lyrics1`）。`active_word` 由 controller 内部用 `compute_active_word` + 当前行 words + 实时 position 算出；用 `_last_active` 去重避免 PositionMs tick 内字未变也重复 push。纯输出, 不接收 D-Bus 入站调用。 |
| `cover_provider.py` | `CoverController` + `CoverImageProvider` | `image://covers/<url>\|<size>\|<radius>` 的图片提供者；圆角裁剪、并发上限 6、磁盘命中秒级返回、未命中异步下载。provider 内部对已解码 + 圆角后的 `QImage` 做有界 LRU（key 含 path / mtime / size / target / radius），列表滚动重复命中时不再反复读盘和重绘圆角。 |

## 适配器与基础设施

| 文件 | 作用 |

## 与 QML 的契约

- 所有控制器都以 **context property** 形式注入（`AppController` / `HomeController` / `PlayerController` ...），QML 端按驼峰名直接访问。
- 长耗时操作用 `@asyncSlot` 装饰，QML 调用立即返回；状态变化经 `Signal` 通知 QML 重绑定。
- 列表绑定一律走 `QAbstractListModel` 子类，role 名（`name` / `singers` / `coverUrl` ...）就是 QML `delegate` 里读到的属性名。
- 封面通过 `image://covers/...` URL 间接拉取，绝不让 QML 直接发网络。
